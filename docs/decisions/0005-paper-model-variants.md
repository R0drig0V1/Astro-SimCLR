# 0005: The paper model's architecture variants as orthogonal flags

- **Status:** accepted (2026-11-08, phase 2, task 2.5-models)
- **Implemented by:** `src/astro_simclr/paper_variants.py`, `src/astro_simclr/group_conv.py`,
  `Settings.paper_arch` / `group_fields` / `context` / `rot90_augment` (`config.py`),
  `data.float_input.context_then_normalise`, `training.modules.PaperClassifierModule`
- **Checked by:** `tests/test_paper_variants.py`, `tests/test_group_conv.py`,
  `tests/test_data_float_input.py`; the golden fixture
  `tests/fixtures/paper_model/faithful.npz`

## Context

Phase 2.5 compares single changes against the replication (`carrasco2021`, CD21 PASS). The
2.5-models rows are B7 (a single-pass p4 G-CNN replacing the 4-pass rotation mean), B2'
(the p4m version: exact D4 invariance), B1' (the 63″ context as 3 more channels) and two
control arms: the single-pass model with rot90 augmentation (is exact invariance needed?)
and p4 at 16/32 fields (bias or capacity?). Each comparison must change exactly one thing,
the faithful preset must stay bit-for-bit what produced the CD21 result, and a variant run
must never pass for the replication. Several choices below would otherwise puzzle a reader.

## Decision

1. **Four orthogonal flags, not one variant name.** `paper_arch` (`rot4 | single | p4 |
   p4m`), `group_fields` (int or null), `context` (`none | avgpool63`) and `rot90_augment`
   (bool). The rows are combinations (B1' is `p4` + `avgpool63`; the control arm is
   `single` + `rot90_augment`), and `paper_variants.VARIANTS` names them. A single
   `variant: b7` field would hide which setting changed, and would need a new value for
   every combination 2.6 may pre-register. Flat fields also keep `--set key=value` and the
   flat `Settings` design of the project.
2. **The defaults are the faithful model, and the presets list them.** `PRESETS` and
   `configs/phase2/carrasco2021*.yaml` gain `paper_arch: rot4`, `group_fields: null`,
   `context: none`, `rot90_augment: false`. The resolved faithful settings are unchanged,
   but `preset_report` compares only preset keys: without them, a `p4` run would be
   recorded as `faithful: true` and `compare-reference --ref CD21` would not warn.
3. **The faithful model is untouched in behaviour, and tested so.** `PaperStampClassifier`
   only gains keyword arguments with faithful defaults (`in_channels=3`,
   `rotation_mean=True`), its layers are built and initialised in the same order, and a
   golden fixture generated by running the class **as it was before this change** (git
   commit pinned in `scripts/characterize/paper_model/generate.py`) is reproduced once per
   new flag: 441,075 / 439,557 parameters, every initial tensor, float64 logits. The M1
   oracle mapping (same keys) is unaffected. The G-CNNs are a separate class
   (`GroupStampClassifier`) with the paper's head as a module (`PaperHead`, tested equal to
   the faithful head).
4. **`group_fields` counts fields of conv1-conv2; conv3-conv5 have twice as many; null
   means `32 // |G|`.** The paper's widths are 32/64 maps; with 8/16 p4 fields (4/8 p4m)
   the expanded kernels have exactly the paper's shapes, so B7 and B2' differ from the
   replication by the weight sharing only. `p4` at 16 is the capacity control (~ the
   replication's 211 M MACs). Setting it for `rot4` / `single` is an error, not ignored.
5. **Glorot fans of a group layer are those of the expanded linear map.** Convolutions use
   Keras' convolution convention on the expanded kernel (`fan_in = in_channels·k²`,
   `fan_out = out_fields·|G|·k²`), which is what `xavier_uniform_` would compute for the
   plain convolution the layer becomes. fc1 recast as a 6×6 group convolution on a 6×6 map
   is a dense layer (1×1 output), so its fans are the dense layer's (`in·|G|·36`,
   `out·|G|`): the convolution convention would multiply `fan_out` by 36 and shrink the
   initial weights about 2× below the paper fc1's, a change of initialisation scale that
   the comparison should not carry. Its 64 field biases keep the paper fc1's Glorot bias.
6. **rot90 augmentation lives in the training step, drawn from `[seed, global_step]`.**
   The batches stay device-resident (no data-module change, which the parallel
   `cv-training` task owns), the draw does not consume the global generator (the
   initialisation and the tiling stream are unchanged), it does not depend on the device,
   and a `--resume` reproduces it, like the tiling stream (`numpy.random.default_rng`; a
   torch generator seed keeps only 32 bits).
7. **The context is pooled first, then normalised like the crop, with the crop's NaN
   approximation** (`docs/data.md`, "The 63×63 context"): each channel on [0, 1] with
   minimum 0, the same NaN → 0 rule, one flag for both, means accumulated in float64 so that
   the context commutes exactly with the rotations. It is a flag of the float input path
   only. Alternatives rejected: pooling the stored [0, 1] stamp without re-normalising
   (its scale would depend on pixels outside the crop differently from the crop channels);
   a separate NaN flag for the context (two inconsistent views of the same pixels).
8. **Hand-written group layers, no escnn.** They run as one `F.conv2d` each on every
   backend (the portability rule; escnn's `py3nj` needs Fortran), and the orientation
   permutation is a stack of slices because an advanced index's backward has no
   deterministic MPS kernel. The kernels are re-expanded on every call (no cache, which
   could go stale after `load_state_dict` or an optimizer step in eval mode); this costs
   batch-1 latency, not throughput, and an exported constant-folded model does not pay it.

## Consequences

- A 2.5 run is `train-supervised --preset carrasco2021 --set paper_arch=p4 [...]`; its
  `metrics.json["preset"]` lists the deviations, and CD21 warns.
- The variant flags are rejected for models other than `paper_stamp_classifier`.
- Old checkpoints of `PaperClassifierModule` load unchanged (the new hyperparameters have
  the faithful defaults).
- Invariance is a test of the whole model in float32 and float64 for every invariant
  configuration, so a geometry change (padding, pooling parity) that breaks it fails CI.
